Magic 视界社区版 v0.4.10 · 右键诊断工具
工具版本：1.3 / 2026-11-11

请先把整个压缩包解压到普通文件夹。不要在 ZIP 内直接运行。
保持社区版运行，在发生故障的同一个 Windows 账户中使用。正常双击即可，不需要“以管理员身份运行”。

一、选哪个入口

01-右键慢或无响应.cmd
适用：右键后迟迟不出现菜单、卡住，或“新建／打开方式”等子菜单没有反应。
按 Enter 开始后：
  1. 对出问题的对象右键一次，等待约 10 秒。
  2. 如果出现菜单，再展开出问题的子菜单，等待约 10 秒。
  3. 回到诊断窗口按 Enter 结束；最长自动记录 90 秒。
  4. 将桌面“Magic右键诊断结果”文件夹内本次生成的 ZIP 发回。

02-Windows菜单缺失.cmd
适用：社区版自定义项还在，但 Windows 的新建、打开方式、属性等项目缺失，或仅有“重试读取 Windows 菜单”。
先按同样步骤复现，点一次“显示更多选项”或“重试读取 Windows 菜单”（若存在）。
结束实际事件记录后，脚本会询问问题对象：
  - 桌面空白处：直接按 Enter。
  - 文件／文件夹／快捷方式：粘贴这个对象的完整本机路径，再按 Enter。
  - 输入 S：跳过独立菜单读取。
随后会读取首层、完整菜单及“新建／打开方式”子菜单，每次读取最多等待 12 秒。
只读取条目，不执行任何菜单命令。不要主动选“删除”等破坏性菜单来复现。
最后将桌面“Magic右键诊断结果”中的本次 ZIP 发回。

03-快捷方式与子进程诊断.cmd
适用：已经采集到 Shell menu worker ended，进一步核对出问题的快捷方式。
不再等待手工右键，直接粘贴发生故障的 .lnk 完整路径（可用 Shift+右键→复制文件地址），不要填启动后的 .exe 路径。
只查询首层和完整菜单；仍使用已经安装的 v0.4.10，不打开快捷方式或执行菜单命令。
新增记录：子进程退出码、是否由诊断器主动回收、每秒 CPU/内存样本、最后执行阶段。
退出码只有在“清理前已经退出”时才可用来判断自然退出；诊断超时主动回收不能当作应用崩溃。
如果两个查询都成功，仍需要继续核查正式点击链路，不能认定原问题消失。
将桌面“Magic右键诊断结果”中本次新 ZIP 发回即可。

04-无调试器模块诊断.cmd
适用：已确认快捷方式查询异常退出，或 r3 观察器触发“发现调试器”的第三方保护提示。
请使用全新解压的 r4 文件夹；不要继续运行 r3 的 04，不要将新旧工具文件混放。
输入同一个故障快捷方式 .lnk 路径；无需再次手动右键。
只通过普通 Process.Modules 枚举自己新建的查询子进程；没有调试器附加、断点、线程暂停或异常拦截。
新增记录：已加载模块的文件名、版本、公司和首次／末次观察时间，以及枚举失败、截断和采集开销。
常规等待期间每秒最多枚举一次，每个请求结束时补采一次；同一子进程总计最多 48 次、256 个唯一模块，查询结束即停止。
模块出现仅证明它被加载，不能单凭模块名称认定原始崩溃原因。未采到模块也不代表没有短暂加载。
不生成内存转储、不记录窗口内容、不上传；无需管理员权限，不需要卸载软件或关闭保护。
本入口不再获取异常子码或异常地址。如果仍有 Windows 应用错误记录，会一起保留原有日志证据。
历史 -ObserveOwnedCrash 参数在 r4 中只转为普通模块枚举并给出提示，不能重新开启调试观察。

两种问题同时存在时，优先使用 02；它也包含 01 的事件记录。
Dock／顶栏自定义菜单可通过 01 记录窗口响应；02 的独立查询针对桌面 Windows Shell 菜单。

二、请同时告知

- 出问题的对象：桌面空白、普通文件（写扩展名即可）、文件夹、快捷方式或回收站。
- 是全部菜单消失，还是少了某些 Windows 功能；具体少了哪些。
- 等待多少秒；只第一次慢还是每次慢。
- Windows 文件资源管理器对同一个对象的右键是否正常。
- 方便时附两张自行截取的菜单截图：社区版 / Windows 资源管理器。

三、记录什么

- 实际运行组件的版本、摘要、同会话进程、权限等级；不靠安装包名字判断版本。
- 右键按下/松开时间和物理坐标，窗口类、PID、显示/隐藏/菜单/前台事件。窗口边界注明坐标空间。
- 右键之后 12 秒内，最多每 500 毫秒检查一次渲染窗口；单窗口 40 毫秒上限，每轮最多 4 个。
- 当前复现时间附近已有的菜单与请求错误日志。文件读取有大小上限。
- 同期 Windows 应用错误／挂起事件、相关 Shell 扩展注册及菜单策略。
- 02／03／04 另保存独立只读查询的阶段、HRESULT、完整/首层条目数量和子菜单结果。

timeline-ordered.jsonl 是按 UTC 排列的时间线，source 区分实际观察、应用日志和独立查询。
compact-query.json / full-query.json 是独立查询结果，不是当前运行桌面内部抓包。
phases.log 只属于诊断器新建的查询子进程。当前运行桌面的 MAGIC_MENU_TRACE 不会被改动。

四、边界与隐私

不安装软件或证书、不修改注册表/配置、不重启或停止现有社区版/Explorer、不调用 UI Automation。
不录屏、不记录键盘或普通鼠标移动、不读取文件内容、剪贴板、聊天内容、令牌、完整布局或内存转储。
不会联网上传。报告含进程 ID、窗口类、点击坐标、菜单标签、第三方处理器名称及相关错误；路径尽量脱敏，发送前可自行查看。
“_local-only”是独立查询的本机临时文件，未放入待发送 ZIP；不要将整个诊断结果文件夹发送出去。
独立查询会按 Windows 正常菜单查询方式加载已安装 Shell 处理器，处理器自身的行为不由本工具控制。
所有观察在停止或到时后解除。若系统策略禁止 Add-Type，保留错误报告即可，不要关闭系统安全策略。

五、结果不等于修复

- 没抓到右键事件，不代表菜单正常。观察到右键也只证明系统产生输入，不证明主程序已经处理。
- 独立查询成功，不代表实际桌面显示成功；桥接、租约和渲染链仍可能出问题。
- 未找到日志或事件，不代表没有异常。
- 完整菜单比首层条目多是正常设计，不能只凭数量差异判断缺项。
- 不同用户的 Shell 扩展、权限和系统语言可能不同，需要结合他们的报告判断。
- 脚本没有替换 v0.4.10；它是诊断工具。

独立查询仅支持摘要匹配的 v0.4.10（源码 760d510）。其它版本仍可记录实际事件和现有日志，但自动跳过未知查询协议。
r3 的调试附加会被部分受保护 Shell 组件识别，影响原始行为；本版已移除该实现。
v0.4.10 已包含 9469fd1 等早先菜单修复；11月10日新增的 8d5a285（访问被拒绝时的桌面菜单备用查询）尚未包含在该安装包，不能宣称此类个案已经解决。

六、可选参数（给开发者）

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ContextMenu.ps1 -Mode MissingWindows -Seconds 90 -DataRoot "D:\MagicData"

-DataRoot 仅在自动识别不到数据目录时指定。不要填程序目录。
-InstallDirectory 仅在多处程序同时运行时指定正确安装目录。
-NoPrompt 供自动检查使用；-SkipCapture / -SkipQuery 可分别关闭事件观察或独立查询。
默认输出到当前账户桌面；可用 -OutputDirectory 指定其它可写目录。
脚本只为自身进程设置执行策略，不持久修改 PowerShell 策略。
